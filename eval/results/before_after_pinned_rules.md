# Before / after: pin two rule chunks in every prompt

Generated by `eval/before_after.py` from the result files listed below; do not edit by hand.

## Hypothesis

The rules `rule:sales-revenue-definition`, `rule:province-names` apply across many questions, but a question's embedding is often not close to the rule text, so they drop out of the top-k. In the default `full` runs q12 and q26 failed for that reason (the rule was not in the starting context and the agent did not call `search_schema` for it). Pinning them next to `relationships` should fix such questions, at the price of more prompt tokens.

## What changed (one variable)

`RetrievalParams.pinned_rules = ('rule:sales-revenue-definition', 'rule:province-names')` (`eval/run.py --pin-rules`). The pinned chunks are placed right after `relationships` in every starting prompt, are removed from the ranking so nothing is duplicated (`k_schema` = 5 still counts ranked chunks), and add the DDL of the tables they name, like a retrieved rule (`rule_tables`). Unchanged: system prompt, k_schema, k_examples = 1, min_score = 0.35, examples, agent loop, max_steps, stop condition and the `search_schema` tool.

## Why these two rules (evidence outside the test set)

Counted from `data/examples.jsonl` (44 few-shot examples; written before the test set was analysed, not the test set):

| evidence | examples | share |
|---|---|---|
| trap `cancelled_refunded` (must drop cancelled/refunded — part of the sales rule) | 17 | 39% |
| SQL uses the sales formula `quantity * unit_price - discount` | 9 | 20% |
| trap `province_aliases` | 4 | 9% |
| any of the three | 20 | 45% |

For comparison, the other traps: `duplicate_customers` 6, `null_dates` 5, `multi_payment` 4.

## Decision

Rule fixed in CLAUDE.md before the after runs (its reading below — every run, per-question count of correct runs — was written into this script before the after runs too): switch the default on only if, for `full`, EX is higher in every after run than in every before run, valid SQL rate does not drop, and fewer questions go right→wrong than wrong→right.

- PASS — EX of every after run > every before run: after [0.9, 0.9] vs before [0.8667, 0.8667]
- PASS — valid SQL not lower: after [1.0, 1.0] vs before [1.0, 1.0]
- PASS — right→wrong (0: –) < wrong→right (1: q12)

**Result: PASS — switch the default on.**

## Limitations

- 30 questions: one question = 3.3 percentage points of EX; two runs per side.
- The two pinned rules were picked from the error analysis of the same test set (there is no dev split), so the after numbers are optimistic for unseen questions; the examples count above is the only evidence from outside the test set.
- The course proxy is not deterministic at temperature 0: the same prompt can give different SQL, so a question that flips in only one run may be noise.
- Recall is measured on the starting prompt only; it says nothing about whether the model uses the rule.

## Not done here (proposals)

- q25: AND/OR precedence in the WHERE clause (prompt guidance or an example), a separate experiment.
- q26/q28: English questions answered with `name_th`; tell the model to use `name_en` for English questions (system prompt change, a separate experiment).
- Agent stop condition: an exploratory query can end up as the final answer; requiring an explicit final SQL would need its own before/after.
- A dev split (or new hard questions) to choose pinned rules without using the test set — needs the owner's decision, the test set is locked.
